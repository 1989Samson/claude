The logic, stated so any number is defensible by derivation.

Three premises. FLV is the forced auction floor, OLV the orderly 90 to 180 day result, FMV the motivated-buyer value. The OLV to FMV spread of 20 to 40 percent is from ASA-aligned appraisal practice, not invented. FLV and the asking-to-FMV haircut are flagged assumptions until calibrated.

Currency. Each point stores its own currency. USD points convert to CAD at the rate on the Assumptions tab, sourced and dated. Nothing is silently mixed.

Point to band. Each point is normalized to the class reference spec by dividing out its own hours, condition, packaging, and configuration multipliers, converted to an FMV estimate by source type, then weighted by source quality and by recency, which is a real decay by point age, not a label. The class FMV is that weighted central. OLV and FLV follow by the ratios above.

Valuing a unit. Class FMV reference, scaled by rating, re-adjusted for the unit's own spec. Scaling is currently linear in rating, which understates economies of scale on units far from the reference. Stated, not hidden.

Confidence. A class stays Indicative until it holds verified sold or auction points. Asking-only data never reads above Indicative. This is deliberately strict.

What it cannot yet do. It has not been backtested, so it does not know its own error. A world-class version validates FMV against known sold prices and reports a median error band. That requires verified sold data, the gating dependency.

Auto-update path. A scheduled job pulls newly closed auction results (Ritchie Bros Price Results, IronPlanet, Maynards on BidSpotter, GovPlanet, mining auctioneers), normalizes each lot, and emits the JSON the Import box accepts. Browsers cannot run that job, so it lives outside this page. Production points the app at a hosted database the job writes to, removing the paste step. Build it once in Claude Code.
